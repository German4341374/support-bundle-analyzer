# Governance

The project uses a maintainer-led model. Maintainers review changes, publish releases, coordinate security response and decide protocol/schema evolution. Decisions with long-term architectural impact are recorded as ADRs. Compatibility-breaking changes require a documented migration path and a major version according to Semantic Versioning.

Contributors gain responsibility through sustained, technically sound participation. No contributor is entitled to access private vulnerability reports or release credentials solely because they have contributed code.
